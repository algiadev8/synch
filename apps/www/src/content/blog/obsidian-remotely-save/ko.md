**Remotely Save는 내가 고른 클라우드 저장소를 통해 Obsidian 보관함을 동기화하는 플러그인입니다.** 컴퓨터와 휴대폰에 각각 설치한 뒤, 같은 저장소 계정과 원격 보관함에 연결하면 됩니다. 다른 기기로 옮겨 작업하기 전에는 양쪽에서 동기화를 마쳐야 합니다.

이 글에서는 Dropbox로 처음 연결하는 과정을 설명합니다. 두 번째 기기에 노트를 내려받고, 그곳에서 수정한 내용이 첫 번째 기기로 돌아오는 것까지 확인해 보겠습니다. 이미 연결했는데 문제가 있다면 아래의 ‘동기화가 안 될 때’부터 확인하세요.

Remotely Save는 Obsidian 공식 Sync 서비스와 별개인 커뮤니티 플러그인입니다. 저장소의 용량, 접근 권한, 복구 수단은 직접 관리해야 합니다.

## 어떤 저장소를 무료로 쓸 수 있나요?

플러그인의 무료 연결 기능과 클라우드 저장소 요금은 별개입니다. 연결 기능이 무료여도 저장 용량이나 API 사용량에 따라 비용이 발생할 수 있습니다.

| 저장소 | 플러그인 기능 구분 | 미리 확인할 사항 |
| --- | --- | --- |
| Dropbox | 무료 | 남은 용량과 모든 기기에서 사용할 계정 |
| S3 호환 저장소 | 무료 | 버킷, 엔드포인트, 인증 키, 저장·API 요금 |
| WebDAV | 무료 | 서버 주소, 인증 방식, 호환성 |
| 개인용 OneDrive, App Folder | 무료 | 기존 폴더가 아닌 앱 전용 폴더 사용 |
| 개인용 OneDrive, Full | PRO | 앱 전용 폴더 밖에 접근할 때 필요 |
| Google Drive | PRO | 해당 기능 활성화와 별도 인증 절차 필요 |
| Box, pCloud, Yandex Disk, Koofr, Azure Blob | PRO | 연결 기능과 저장소 자체의 이용 제한 |

선택 전에는 프로젝트의 [지원 서비스 목록](https://github.com/remotely-save/remotely-save/blob/master/docs/services_connectable_or_not.md)을 확인하세요. 다른 무료 동기화 방식은 [무료 Obsidian 동기화 비교](/ko/blog/free-obsidian-sync/)에서 다룹니다.

## Dropbox로 처음 동기화하기

아래 절차는 **새로 동기화를 설정하는 경우**를 기준으로 합니다. 두 기기에서 이미 같은 보관함을 따로 수정했다면, 먼저 각각의 사본을 보관하세요. 어느 쪽을 남길지 첫 동기화에 맡기면 안 됩니다.

### 1. 보관함을 백업하고 테스트 노트 만들기

노트가 모두 들어 있는 기기에서 시작하세요. 동기화 대상 폴더 밖에 보관함을 복사하고, 그 사본이 제대로 열리는지 확인합니다.

실제로 사용할 보관함에는 동기화 도구를 하나만 적용하세요. Remotely Save가 Dropbox에 직접 연결하므로, 보관함을 Dropbox 데스크톱 앱의 동기화 폴더에 넣어 이중으로 동기화할 필요가 없습니다.

처음에는 `Notes-Sync-Test`처럼 구분하기 쉬운 이름으로 작은 테스트 보관함을 만들어 보세요. 같은 Dropbox 계정에서 이미 사용 중인 원격 보관함 이름은 피합니다. ‘동기화 확인’ 노트를 만들고 휴대폰에서 알아볼 수 있는 문장을 적어 두세요.

### 2. Remotely Save 설치하기

Obsidian의 **설정 → 커뮤니티 플러그인**에서 플러그인 사용을 허용한 다음, 플러그인 목록에서 **Remotely Save**를 검색해 설치하고 활성화합니다. 동기화를 실행하기 전에 Remotely Save 설정을 여세요.

아래는 구버전 Obsidian 화면입니다. 현재 버전과 메뉴 이름이나 배치가 다를 수 있습니다.

### 3. Dropbox 계정 연결하기

Remotely Save 설정의 **Choose service**에서 **Dropbox**를 선택하고 **Auth**를 누릅니다. 안내된 링크를 브라우저에서 열어 사용할 Dropbox 계정이 맞는지 확인한 뒤 연결을 허용하세요. Obsidian으로 돌아오면 연결된 상태인지 확인합니다.

![Dropbox 선택 메뉴와 Auth 버튼이 표시된 Remotely Save 설정 화면](./dropbox-choose-service.webp)

*Dropbox를 선택한 뒤 Auth를 누르세요.*

문서에 따르면 파일은 Dropbox의 `/Apps/remotely-save` 아래에 저장됩니다. 기본 설정에서는 보관함 이름으로 원격 보관함을 구분하므로, 다른 기기에서도 같은 이름을 사용해야 합니다. 자세한 접근 범위는 [Dropbox 연동 설명](https://github.com/remotely-save/remotely-save#dropbox)을 참고하세요.

![Dropbox 연결 후 Revoke Auth 버튼과 연결 상태가 나타난 화면](./dropbox-connected.webp)

*이 화면에서는 연결 후 Auth가 Revoke Auth로 바뀝니다. 계정 연결이 끝났다면 동기화를 실행해 노트를 전송하세요.*

### 4. 암호화는 첫 업로드 전에 설정하기

종단간 암호화를 사용할 생각이라면 처음 업로드하기 전에 설정하세요. 비밀번호는 비밀번호 관리자에 보관하고, 선택한 암호화 형식도 기록해 둡니다. 모든 기기에서 같은 형식과 비밀번호를 사용해야 합니다.

프로젝트는 [Rclone Crypt와 OpenSSL 형식](https://github.com/remotely-save/remotely-save/blob/master/docs/encryption/README.md)을 안내합니다. 저장소 계정을 연결했다고 암호화가 자동으로 켜지는 것은 아닙니다. Dropbox 연동에서는 보관함 이름도 암호화되지 않습니다.

이미 사용 중인 원격 보관함의 비밀번호나 암호화 형식을 문제 해결 목적으로 바꿔 보지는 마세요. 읽을 수 있는 로컬 사본을 확보하고, 암호화 문서를 확인한 뒤 변경해야 합니다.

### 5. 첫 동기화 실행하기

Obsidian 왼쪽 리본의 Remotely Save 동기화 아이콘을 누르거나 명령어 팔레트에서 해당 동기화 명령을 실행하세요. 완료될 때까지 Obsidian을 열어 두고, 오류가 나오면 두 번째 기기를 연결하기 전에 해결합니다.

![동기화 버튼 위치와 진행 알림을 보여 주는 Obsidian 화면](./dropbox-run-sync.webp)

*표시된 동기화 버튼을 누르고, 완료를 확인한 뒤 다른 기기로 넘어가세요.*

테스트하는 동안에는 주기적 자동 동기화를 꺼 두고 직접 실행하는 편이 확인하기 쉽습니다. 파일 크기 제한과 경로 제외 설정도 살펴보세요. 동기화가 끝났어도 제외된 첨부파일은 전송되지 않을 수 있습니다.

### 6. 휴대폰이나 두 번째 컴퓨터 연결하기

1. 첫 기기와 **같은 이름**으로 비어 있는 로컬 보관함을 만듭니다. iPhone이나 iPad에서는 이 보관함의 **Store in iCloud** 옵션을 끕니다.
2. 새 보관함에 Remotely Save를 설치하고 활성화합니다.
3. Dropbox를 선택하고 첫 기기와 같은 계정을 연결합니다.
4. 암호화를 켰다면 형식과 비밀번호를 맞춥니다. 원격 저장 위치를 따로 지정했다면 그것도 같아야 합니다.
5. 수동으로 동기화를 실행하고 완료될 때까지 앱을 열어 둡니다.
6. ‘동기화 확인’ 노트에서 첫 기기에 적은 문장이 보이는지 확인합니다.

비어 있는 보관함으로 시작하는 이유는 서로 다른 수정본을 처음부터 섞지 않기 위해서입니다. 첫 기기의 백업은 계속 보관하세요.

### 7. 반대 방향으로도 확인하기

두 번째 기기의 ‘동기화 확인’ 노트에 문장을 하나 더 쓰고 동기화하세요. 이어서 첫 기기를 동기화했을 때 그 문장이 나타나면 양방향 전송이 확인된 것입니다. 첨부파일을 자주 쓴다면 작은 파일도 하나 보내 보세요.

여기까지 확인한 뒤 자동 동기화를 켜고 평소처럼 사용하면 됩니다. 기기를 바꿀 때는 쓰던 기기를 먼저 동기화하고, 새로 열 기기도 동기화한 다음 편집하세요.

## 휴대폰에서는 앱을 열어 둬야 합니다

Remotely Save는 Obsidian 모바일에서도 사용할 수 있습니다. 다만 **앱을 열어 둔 상태에서 동기화한다**고 생각하는 편이 좋습니다. 자동 동기화를 설정해도 운영체제가 앱을 중단하면 계속 실행된다고 보장할 수 없습니다.

처음 내려받을 때는 첨부파일까지 받을 시간을 주세요. 중간에 끊겼다면 앱을 다시 열어 오류를 확인하고, 필요한 파일이 도착한 뒤 편집하세요.

프로젝트의 [제한 사항](https://github.com/remotely-save/remotely-save#limitations)에는 50 MB 이상의 큰 파일을 비롯한 모바일 성능 문제가 안내되어 있습니다. 노트는 오는데 PDF나 녹음 파일만 빠진다면 큰 파일 제외 설정부터 확인해 보세요. 다른 방법도 비교하려면 [iPhone과 Android 사이의 Obsidian 동기화](/ko/blog/obsidian-iphone-android-sync/)를 참고하세요.

## 동기화가 안 될 때 확인할 것

작은 테스트 노트 하나로 각 기기에서 차례대로 수동 동기화를 실행해 보세요. 어느 기기에서 어떤 오류가 발생하는지 적어 두면 업로드 문제인지, 다운로드 문제인지, 특정 파일만 빠지는지 구분하기 쉽습니다.

| 증상 | 확인할 항목 | 다음 조치 |
| --- | --- | --- |
| 계정 인증이 끝나지 않음 | 브라우저의 로그인 계정, Obsidian 복귀 여부 | 인증을 다시 진행하고 연결 상태 확인 |
| 완료됐는데 다른 기기의 보관함이 비어 있음 | 계정, 보관함 이름, 원격 위치 | 두 기기의 설정과 첫 기기의 업로드 결과 비교 |
| 암호화된 파일을 읽지 못함 | 암호화 형식과 비밀번호 | 읽을 수 있는 사본을 보관한 뒤 기존 설정과 대조 |
| 노트는 오는데 첨부파일이 빠짐 | 파일 크기 제한, 제외 경로 | 빠진 파일의 크기와 경로, 오류 메시지 확인 |
| 휴대폰에서 앱을 열어야 따라잡음 | 앱 중단과 동기화 시점 | 편집 전후에 앱을 열고 수동 동기화 |
| WebDAV나 S3 연결 실패 | 주소, 인증정보, 권한, 오류 내용 | 해당 제공자의 설정 문서에 따라 확인 |
| 노트가 중복되거나 수정 내용이 사라짐 | 동시 편집, 다른 동기화 도구 | 다른 기기에서 편집을 멈추고 모든 사본 보존 |

문제가 해결되는지 보려고 원격 보관함을 지우거나 플러그인을 재설치하거나, 유일하게 온전한 로컬 사본을 삭제하지 마세요. 파일이 사라졌다면 남은 사본부터 보관하고 백업과 복구 기록을 확인하세요. [동기화 충돌과 누락된 노트에 관한 글](/ko/blog/obsidian-sync-conflicts/)에서도 원인과 복구 시 주의점을 다룹니다.

### Google Drive에 올린 파일이 보이지 않는 경우

Google Drive 연결은 **PRO 기능**입니다. 해당 기능을 활성화한 뒤 플러그인 안에서 계정 인증을 진행해야 합니다.

또한 [Google Drive 연동 문서](https://github.com/remotely-save/remotely-save/blob/master/docs/remote_services/googledrive/README.md)에 따르면 플러그인은 자신이 만든 파일과 폴더에 접근합니다. Drive 웹사이트에서 직접 올린 보관함은 플러그인에 보이지 않습니다. 로컬 보관함을 백업한 다음, Obsidian 안에서 플러그인을 통해 업로드하세요. 방식별 차이는 [Google Drive 동기화 가이드](/ko/blog/obsidian-google-drive-sync/)에서 확인할 수 있습니다.

### OneDrive 계정이나 빈 파일에서 오류가 나는 경우

무료 연결 기능은 **개인용 OneDrive의 App Folder**를 대상으로 합니다. 회사·학교 계정을 같은 방식으로 쓸 수 있다고 가정하면 안 됩니다. 개인용 OneDrive 전체 접근은 별도 PRO 기능입니다.

[OneDrive 문서](https://github.com/remotely-save/remotely-save/blob/master/docs/remote_services/onedrive/README.md)에는 API가 빈 파일 업로드를 허용하지 않는다는 설명도 있습니다. 빈 Markdown 노트에서 오류가 난다면 플러그인의 빈 파일 처리 설정을 확인하거나, 노트에 실제 내용을 적은 뒤 다시 시도하세요.

## 오래 쓰려면 챙겨야 할 것

Remotely Save의 `data.json`에는 민감한 설정이 들어갈 수 있습니다. 공개 Git 저장소, 문의용 스크린샷, 이슈 첨부파일에 포함하지 마세요. 오류를 공유할 때도 토큰과 인증정보, 비공개 노트 내용은 지워야 합니다.

무료 버전에는 기본 충돌 처리가 있고, 고급 스마트 충돌 처리는 PRO 기능입니다. 어느 쪽이든 두 기기에서 같은 노트를 수정했다면 양쪽 내용을 확인하세요. 병합 전 사본을 남기고, 병합 결과가 다른 기기에서도 맞는지 확인한 뒤 작업을 이어갑니다.

백업은 동기화 대상 밖에 보관하세요. 동기화는 삭제나 잘못된 수정도 전파할 수 있습니다. 복구할 수 있는 범위는 실제로 남아 있는 백업과 기록에 달려 있습니다.

## 다른 도구를 고르는 편이 나은 경우

원하는 저장소가 있고 그 설정을 직접 관리할 수 있다면 Remotely Save는 잘 맞는 선택입니다. 두 기기에서 정상적으로 동작하는 것을 확인했다면 굳이 바꿀 이유도 없습니다.

반대로 저장소 연결과 관리를 줄이고 싶다면 호스팅 서비스를 비교해 보세요.

| Remotely Save | Dropbox, WebDAV, S3 등 원하는 저장소 사용 | 연결 설정, 인증정보, 제외 항목, 복구 관리 |
| Obsidian Sync | 공식 통합 서비스 선호 | 유료 구독과 동기화 항목 선택 |
| Synch | 오픈소스·종단간 암호화 기반 호스팅 서비스 선호 | 보관함과 첨부파일 크기에 맞는 요금제 선택 |

[Synch](/ko/)는 동기화 서버를 제공하므로 별도 저장소 계정을 연결할 필요가 없습니다. 기기 간 직접 동기화, 셀프호스팅, Git도 고려한다면 [Obsidian Sync 대안 비교](/ko/blog/obsidian-sync-alternatives/)를 참고하세요.
